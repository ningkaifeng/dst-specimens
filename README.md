# 复杂治理标本库 · Complex Governance Specimen Library

对一个正在运转的真实系统做一次结构诊断，并在结果尚未发生之前，白纸黑字写下判断——然后等现实来对照。

---

## 一、这份仓库在做什么

**标本** = 一次实时诊断 + 一个事前判断 + 一条可被证伪的修正条件。

每份标本回答同一个问题：**这个系统还能不能维持自身？** 它不评价好坏、不预测输赢、不给政策建议，只标出三件事：

1. 这套系统现在处在什么状态；
2. 它最该动的那一处在哪里；
3. 什么情况下说明这个判断错了。

## 二、为什么公开

三个时间戳构成本库的全部价值：

| 阶段 | 做什么 | 纪律 |
|---|---|---|
| **T0** | 结果未知时写下判断 | **一字不改，提交即锁定** |
| **T1** | 事件发生后追加回看 | 只追加，不修改 T0 |
| **T2** | 事后复盘，校准方法 | 只追加 |

一个事前判断，如果没人看见、没有时间戳，就等于没写。这份仓库的 git 提交历史，就是"我在这一天这样说过"的证据——**它是可查的、不可回溯修改的、第三方可以核对的**。

## 三、判断可能是错的，这是设计的一部分

T0 不是结论，是假说。

本库不靠"我一直说对了"建立可信度，靠三件事：

- 事前说了什么，有据可查；
- 事后偏在哪里，如实记录；
- 偏了以后，方法改了什么，也写下来。

能被证明错，才有资格被认真看待。

## 五、目录

```
T0/      事前判断原件（.docx 原件 + .md 便于检索）——只增不改
T1/      观测表与回看记录——事件回来后追加
specs/   诊断方法本体：语法说明书 / 判据 / 写作纪律 / 领域对接口径 / 操作手册
logs/    外部评审纪要（含语法层面评审与"断奶清单"）
```

## 六、怎么读

- **想快速了解这套方法** → `specs/存续域语法使用说明书_v1.2.md`
- **想检验我们说得准不准** → 看 `T0/`，然后回来看 `T1/` 的回看记录
- **想自己拿这套方法做诊断** → `specs/操作手册_v1.0.md` + `specs/复杂系统诊断的判据_v1.1.md`
- **想看它被质疑过什么** → `logs/`

## 七、唯一的硬规则

**T0 文件提交后不再修改。**

发现判断有误、措辞有偏差、事实有更新，一律在 `T1/` 追加更正，不回改 T0。这条规则让步一次，整库的证据价值就归零。

## 八、与作者其他工作的分工

| 尺度 | 对象 | 时间性 | 能否被证伪 |
|---|---|---|---|
| 治水学论纲（理论） | 方法本身 | 无时间 | 否 |
| 决策显影库 | 单个决策事件 | 过去 | 否（事后显影） |
| 思想显影库 | 理论体系 | 跨时代 | 否 |
| **本库（标本）** | **在运行的真实系统** | **现在 → 未来** | **是，而且必须** |

前三者解释已经发生的事；本库是唯一往前看、并且可能被现实推翻的一条。
